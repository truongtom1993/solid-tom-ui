## COMPONENT IDENTITY
- **Import**: `import { Checkbox } from 'solid-tom-ui';`
- **Export**: `Checkbox` (named export)
- **Framework**: SolidJS
- **Purpose**: Single `<input type="checkbox">` — supports both **controlled** (`checked` prop) and **uncontrolled** (`defaultChecked` prop) modes

---

## TYPE SIGNATURE

```ts
type CheckboxBaseProps = {
  id?: string;
  name?: string;
  value?: string;
  indeterminate?: boolean;
  disabled?: boolean;
  size?: 'xs' | 'sm' | 'md' | 'lg' | 'xl';
  color?: 'default' | 'neutral' | 'primary' | 'secondary' | 'accent' | 'info' | 'success' | 'warning' | 'error';
  class?: string;
  onChange?: (checked: boolean) => void;
};

// Uncontrolled — DOM owns state
type CheckboxUncontrolled = CheckboxBaseProps & {
  defaultChecked?: boolean;
  checked?: never;
};

// Controlled — parent owns state
type CheckboxControlled = CheckboxBaseProps & {
  checked: boolean;
  defaultChecked?: never;
};

type CheckboxProps = CheckboxUncontrolled | CheckboxControlled;
```

## PROP REFERENCE

| Prop             | Type                                                        | Required | Description                                                                                        |
|------------------|-------------------------------------------------------------|----------|----------------------------------------------------------------------------------------------------|
| `checked`        | `boolean`                                                   | ❌ NO    | **Controlled mode** — parent owns state. Mutually exclusive with `defaultChecked`.                  |
| `defaultChecked` | `boolean`                                                   | ❌ NO    | **Uncontrolled mode** — sets initial `checked` via DOM ref on mount only. Mutually exclusive with `checked`. |
| `indeterminate`  | `boolean`                                                   | ❌ NO    | Always controlled. Shows dash/minus visual; blocks user toggling. Synced to `input.indeterminate` DOM property via `createEffect`. |
| `id`             | `string`                                                    | ❌ NO    | `id` on `<input>` — auto-generated if omitted                                                      |
| `name`           | `string`                                                    | ❌ NO    | `name` attribute for native form submission grouping                                               |
| `value`          | `string`                                                    | ❌ NO    | HTML `value` attribute — submitted with form data when checkbox is checked. Standard HTML behavior. |
| `disabled`       | `boolean`                                                   | ❌ NO    | Disables input; prevents toggling                                                                   |
| `size`           | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'`                    | ❌ NO    | Visual size                                                                                        |
| `color`          | `'default' \| 'neutral' \| 'primary' \| ...`               | ❌ NO    | Fill color when checked                                                                             |
| `class`          | `string`                                                    | ❌ NO    | Extra Tailwind classes on `<input>`                                                                 |
| `onChange`       | `(checked: boolean) => void`                                | ❌ NO    | Fires with `true`/`false` on user interaction. NOT fired when `indeterminate` or `disabled`.        |

## CONTROLLED vs UNCONTROLLED

### Controlled — `checked` prop

Parent owns state. Component always renders what `checked` says.

```tsx
const [agreed, setAgreed] = createSignal(false);

<Checkbox
  checked={agreed()}
  onChange={val => setAgreed(val)}
  color="primary"
  size="md"
/>
```

**Use when**: you need to toggle from outside, derive state from other signals, or sync with form stores.

### Uncontrolled — `defaultChecked` prop

DOM owns state after mount. Use `onChange` to read changes.

```tsx
<Checkbox
  defaultChecked={false}
  onChange={val => console.log(val)}
  color="primary"
  size="md"
/>
```

**Use when**: simple standalone checkbox, no external state needed, native form submission.

> ⚠️ Never mix `checked` and `defaultChecked` — TypeScript enforces mutual exclusion.
> ⚠️ Never pass a reactive signal to `defaultChecked` — it's mount-only, updates are ignored.

## INDETERMINATE STATE

`indeterminate` is always **controlled** — parent must manage when to show/clear it.

- Synced to DOM property `input.indeterminate` via `createEffect` — reactive updates work
- Sets `data-indeterminate="true"` attribute for CSS targeting
- `onClick` calls `e.preventDefault()` — user cannot toggle
- `onChange` is never fired

```tsx
// Select-all pattern — indeterminate reacts to child changes
const [items, setItems] = createSignal([
  { label: 'A', checked: true },
  { label: 'B', checked: false },
]);
const allChecked = () => items().every(i => i.checked);
const someChecked = () => items().some(i => i.checked);

<Checkbox
  checked={allChecked()}
  indeterminate={someChecked() && !allChecked()}
  onChange={val => setItems(prev => prev.map(i => ({ ...i, checked: val })))}
/>
```

## FORM USAGE — `name` + `value`

`value` is a standard HTML attribute. When checkbox is **checked** and form is submitted, browser sends `name=value`. When unchecked, nothing is sent.

```tsx
<form onSubmit={e => {
  e.preventDefault();
  const data = new FormData(e.currentTarget);
  console.log([...data.entries()]);
  // checked: [["interests", "typescript"]]
  // unchecked: []
}}>
  <label class="flex cursor-pointer items-center gap-2">
    <Checkbox name="interests" value="typescript" defaultChecked={false} />
    <span>TypeScript</span>
  </label>
  <label class="flex cursor-pointer items-center gap-2">
    <Checkbox name="interests" value="solidjs" defaultChecked={false} />
    <span>SolidJS</span>
  </label>
  <button type="submit">Submit</button>
</form>
```

## ADDING A LABEL

```tsx
// Label to the right (most common)
<label class="flex cursor-pointer items-center gap-2">
  <Checkbox defaultChecked={false} color="primary" size="md" />
  <span>Accept terms</span>
</label>

// External label via id
<label for="terms-cb" class="cursor-pointer text-sm">Accept terms</label>
<Checkbox id="terms-cb" defaultChecked={false} color="primary" />
```

> ℹ️ Always add `cursor-pointer` to `<label>`.

## INTERNAL DOM STRUCTURE

```
<input
  type="checkbox"
  id="{id | auto}"
  class="checkbox checkbox-{size} checkbox-{color} [class]"
  disabled={disabled}
  name="{name}"                ← only if name prop provided
  data-indeterminate="true"   ← only if indeterminate={true}
  checked={checked}           ← only in controlled mode
  value="{value}"
  onClick={...}               ← preventDefault when indeterminate or disabled
  onChange={...}              ← fires p.onChange with e.target.checked
/>
```

`input.indeterminate` DOM property is synced separately via `createEffect`.

---

## COMMON MISTAKES TO AVOID

| Mistake | Correct approach |
|---|---|
| `<Checkbox checked={sig()} defaultChecked={false} />` | Use one or the other — TypeScript will error |
| Passing reactive signal to `defaultChecked` | Use `checked` prop for reactive control |
| Expecting `onChange` when `indeterminate={true}` | `onClick` is blocked — `onChange` never fires |
| Managing indeterminate internally | `indeterminate` is always a controlled prop — parent drives it |
| Omitting `cursor-pointer` on `<label>` | Always add for correct UX |

## FULL EXAMPLE

```tsx
import { Checkbox } from 'solid-tom-ui';
import { createSignal, For } from 'solid-js';

// 1. Controlled
const [agreed, setAgreed] = createSignal(false);
<label class="flex cursor-pointer items-center gap-2">
  <Checkbox checked={agreed()} onChange={setAgreed} color="success" size="md" />
  <span>I agree ({agreed() ? 'Yes' : 'No'})</span>
</label>

// 2. Uncontrolled
<label class="flex cursor-pointer items-center gap-2">
  <Checkbox defaultChecked={false} onChange={val => console.log(val)} color="primary" size="md" />
  <span>Accept terms</span>
</label>

// 3. Select-all with indeterminate
const [items, setItems] = createSignal([
  { label: 'A', checked: true },
  { label: 'B', checked: false },
]);
const allChecked = () => items().every(i => i.checked);
const someChecked = () => items().some(i => i.checked);

<label class="flex cursor-pointer items-center gap-2">
  <Checkbox
    checked={allChecked()}
    indeterminate={someChecked() && !allChecked()}
    onChange={val => setItems(p => p.map(i => ({ ...i, checked: val })))}
    size="md"
  />
  <span>Select all</span>
</label>
<For each={items()}>
  {(item, idx) => (
    <label class="flex cursor-pointer items-center gap-2">
      <Checkbox
        checked={item.checked}
        onChange={() => setItems(p => p.map((i, n) => n === idx() ? { ...i, checked: !i.checked } : i))}
        size="sm"
      />
      <span>{item.label}</span>
    </label>
  )}
</For>

// 4. Disabled
<label class="flex cursor-pointer items-center gap-2 opacity-50">
  <Checkbox defaultChecked={true} color="neutral" size="md" disabled />
  <span>Cannot change</span>
</label>

// 5. Form with name + value
<form onSubmit={e => { e.preventDefault(); console.log([...new FormData(e.currentTarget)]); }}>
  <label class="flex cursor-pointer items-center gap-2">
    <Checkbox name="lang" value="typescript" defaultChecked={true} size="sm" />
    <span>TypeScript</span>
  </label>
  <button type="submit" class="btn btn-sm btn-primary mt-2">Submit</button>
</form>
```
